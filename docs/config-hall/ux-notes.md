# 配置大厅交互草图

日期：2026-10-23

状态：独立原型已展示并获用户确认；原型本身不调用账号写接口。正式页面已接入真实 API，实际验收见 [实施计划](implementation-plan.md)。

## 设计依据

使用仓库内 `design-taste-frontend` app-screen 流程。抽取方向为 Accent ladder，seed `1675483082`，保留现有 palette/type。

原抽取侧栏结构、一次 shell redraw 得到的 T-frame 都与本站既有顶栏冲突；根据用户明确要求，保留本站顶栏与居中内容，不新增全站侧栏。配色继续使用纸色 `#eee8dc`、森林绿 `#1d332b` 和原站强调色，属于品牌保留；检查时对 `palette-claude`、`palette-cream` 显式豁免。不把旧页面的重阴影、小字、窄屏溢出复制进新增界面。

## 数据与任务清单

- 对象是玩家配置：标题、说明、职业、作者、分享码、使用人数、点赞、更新时间。
- 示例为六套配置，人数 0–183，点赞 0–46；不是生产数据。
- 用户多数先选自己的职业，也有人直接粘贴朋友的分享码。
- 最常见动作是复制到自己的角色；该动作在每行直接可见。
- 标题与说明回答“这套配置做什么”，优先于文件内容。
- 使用人数与点赞是辅助选择依据，列中数字右对齐，使用 tabular figures。
- 角色和职业复用本站 RO 职业图标；不引入装饰插画、排行榜奖牌、虚构推荐。
- 分享码是可直接复制的定位工具，不让用户自己拼链接。
- 目标角色属于复制者；职业允许不同，不显示兼容性警告。
- 编辑器只有一次保存：checkbox 决定保存时是否同时发布，说明选填。

## 每屏首先回答的问题

- 大厅：哪套配置适合我，如何复制？列表优先，不增加统计卡或介绍大横幅。
- 复制弹窗：复制给我的哪个角色？不要求填写名称、不让用户选择五份文件。
- 编辑器分享区：这次保存会不会分享/更新？直接显示勾选状态和本次保存的结果。

## 交互决定

- 桌面使用配置列表，职业/作者同列，人数与赞各一列；主按钮在统一末列。
- 手机变为可读的配置条目，保留说明、分享码、人数、点赞与复制；过滤区域压缩，首条配置出现在第一屏。
- 点标题看说明及折叠的五文件预览，不要求新人阅读正文再复制。
- 复制弹窗只选角色；完成后明确“已保存，尚未启用”，提供“去调整配置”。
- 已经复制过仍可再次复制，人数不会重复增加；模拟数据由单一对象维护，列表与详情一致。
- 分享 checkbox 默认勾选，整行可点击；说明展开，标签明确标为“选填”。
- 取消勾选后就地说明“本次只保存个人配置”，不会突然撤回已发布版本。
- 已发布状态显示原分享码，独立提供撤回操作；保存按钮文案跟随勾选结果，让后果可预期。
- 场景切换属于原型预览工具，不进入真实产品界面。

- 复制弹窗另豁免 `covered-text`：打开模态弹窗时背景标题被遮罩遮住是预期交互，不是内容重叠问题；不将该豁免用于普通页面。真实模态使用原生 dialog，支持焦点约束与 Escape 关闭。

## 看图后的调整与判断

1. 阅读顺序：最大区域始终是配置列表，标题/说明先于热度与操作；没有额外统计卡挤占空间。
2. 对齐与留白：桌面字段共用左右边界；平板改为条目，去掉重复的分享码；编辑器保存操作在 900px 桌面首屏可见。
3. 配色：保留本站标识与职业图标，仅用淡色表示选择和分享区域，强调色留给确认/保存。
4. 数据：六套示例由一个数据对象维护；筛选条数实时计算；列表和详情共用点赞/人数；重复复制只增一次人数。
5. 零与缺失：自己的条目显示真实的示例零值；没有说明时给出普通文本，不制造未填写警告。
6. 动作反馈：复制结果说明尚未启用；分享开关变化立即改变保存按钮文案。普通列表无需阅读五文件内容即可完成复制。
7. 手机：首条配置在第一屏 60% 处之前出现；分享区域排在详细配置前；底部保存栏延续现有编辑器习惯，并预留页面尾部空间。

看图后修正的三类问题：平板重复分享码、分享帮助文字过小、手机保存动作离分享开关过远。用户已确认整体布局；正式实现已改用真实账号、数据库内容和完整 KE 配置编辑器。
