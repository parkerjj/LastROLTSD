# KE 配置大厅：需求与现状记录

日期：2026-10-23

开发分支：`codex/profile-hall`

状态：用户已确认完整设计与交互草图；实现和独立审阅已完成，完整行为见 [设计文档](design.md)，验收过程见 [实施计划](implementation-plan.md)。未部署，也未应用生产数据库。

## 目标

降低复杂 KE 配置的使用门槛，让熟悉配置的玩家分享自己的方案，其他玩家能够找到适合自己职业的方案，并复制为自己的配置继续修改。

## 用户已明确的要求

1. 在新分支上开发，相关文档保存在项目 `docs` 目录。
2. 在现有 KE 配置页提供醒目、有吸引力的“共享配置”勾选入口。
3. 分享时将配置镜像复制到新的 shared profile 数据表，与个人配置分开存储。
4. 服务端随机生成形如 `ABC-1234` 的分享码，格式为三个字母、连字符、四位数字。
5. 新增配置大厅页面，展示被分享的配置。
6. 用户可以将共享配置镜像复制到自己的配置表。
7. 成功复制后，共享配置的“使用人数”增加。
8. 支持点赞及点赞数展示。
9. 支持按点赞数、使用人数排序。
10. 支持按职业过滤；职业取自配置创作者的角色。
11. 上述功能均需登录，但不要求 permission level 或邮箱验证。
12. 共享通过配置修改页的 checkbox 与保存操作结合；初次共享和更新共享时，checkbox 默认均勾选。
13. 使用人数与点赞按账号记录；使用人数按成功复制的独立账号去重。
14. 职业只用于大厅筛选，不是权限或兼容性条件，允许跨职业复制。
15. 不额外设置共享条目数量上限。
16. 共享标题使用原配置名称；勾选分享后可填写说明，说明选填，可以为空。

### 已确认的共享与更新交互（2026-10-23）

| 当前配置状态 | checkbox 文案 | 默认值 | 勾选后保存的结果 |
| --- | --- | --- | --- |
| 尚未分享 | 同时将此配置共享给他人 | 勾选 | 保存个人配置，并创建共享快照、生成分享码 |
| 已经分享 | 同时更新共享的配置 | 勾选 | 保存个人配置，并更新对应共享快照，保留分享码 |

修改输入框本身不改变大厅内容，保存时才根据 checkbox 决定是否发布或更新。其他人已经复制到自己账号的配置保持独立，不随共享快照更新。

已确认取消勾选的语义：本次只保存个人配置；尚未分享则不发布，已经分享则保留原有共享版本。取消勾选不等于撤回分享；下次打开编辑器仍默认勾选，不将本次取消状态保存为长期偏好。

## 开始设计时核对的项目现状

| 项目 | 当前行为 | 对新功能的影响 |
| --- | --- | --- |
| 技术栈 | Cloudflare Worker + Hono，前端 Vite + TypeScript，数据库 MySQL 8 | 沿用现有技术栈和 migration 机制 |
| 个人配置 | `ke_profiles` 通过 `user_id + aid + cid + nid` 绑定账号和角色 | 复制时必须明确目标角色，并由服务端验证归属 |
| 配置内容 | `config_text`、`mon_control`、`pickupitems`、`items_control`、`timeouts` 五份原文 | 镜像复制应保留全部内容，包括空字符串与 NULL 的区别 |
| 配置上限 | 每个角色最多 20 套；同角色同账号下名称唯一 | 复制需要处理满额、重名与并发请求 |
| 激活行为 | 同一角色只有一套 active；新建配置默认未激活 | 建议复制结果也默认未激活，由用户检查后主动启用 |
| 职业 | `ke_characters.job_id` 可为空，由 KE 上报角色信息 | 服务端读取具体职业快照；大厅按二阶职业系过滤，并覆盖该分支的初心者、进阶、三转、四转、宝宝与骑乘形态，不限制分享或跨职业复制 |
| 登录 | 网页会话允许 `PENDING_EMAIL`，禁用账号不可用 | 不应为大厅加邮箱验证、等级或 KE 运行权益门槛 |
| 空角色账号 | 当前编辑器要求先通过 KE 绑定角色 | 需要设计无目标角色时的复制提示，不能将缺少角色误报为邮箱或权限限制 |
| 数据迁移基线 | 开始实施前最后一个迁移为 `018_admin_audit_log.sql` | 新增 `019_ke_shared_profiles.sql`；只在隔离的本地 MySQL 测试 schema 运行 |

## 讨论结论与开发方补齐的默认行为

用户已确认的行为见上文；以下保留“建议”字样的部分为开发方补齐，具体采用的完整规则以设计文档为准。

### 共享是可独立更新的快照

- 已确认：首次发布和更新与个人配置保存结合，由默认勾选的 checkbox 控制，见上方交互表。
- 建议同一份原配置只对应一个共享条目，重复提交返回同一分享码。
- 未勾选“同时更新共享的配置”时保存，仅修改个人版本；勾选时才同步本次保存的版本。
- 更新共享版本保留分享码；建议同时保留点赞与使用人数，记录更新时间。
- 他人已经复制的配置始终独立；建议撤回分享也不影响这些副本。
- 建议个人保存与勾选的共享创建/更新在同一事务内完成，失败时不显示整体保存成功。
- 作者可单独撤回分享，撤回后大厅、分享码查询、复制均不可用；恢复沿用原分享码和统计，详见设计文档。
- 删除原配置同步撤回共享；他人已复制的副本保持独立，详见设计文档。

### 复制与使用人数

- 点击复制后选择自己的目标角色；只有一个角色时可默认选择。
- 插入新的 `ke_profiles` 行，使用复制者的账号和目标角色身份，不继承作者的角色标识或 active 状态。
- 五份文件按原文复制，复制者之后通过现有编辑器修改。
- 建议重名时自动添加简短后缀，并提供修改名称的机会；超出 20 套上限则清晰提示。
- 已确认“使用人数”统计成功复制过该条目的独立账号数；开发方补齐：作者复制自己的配置不计入人数。
- 同一账号复制到多个角色、删除后重新复制，均不重复增加人数。
- 建议允许以后再次复制；同一次操作的重复点击、请求重试应幂等。
- 新建个人配置、记录使用者、更新使用人数必须同事务提交；失败不得计数。

### 点赞

- 建议每个账号对每条共享配置最多一个赞，支持取消点赞。
- 点赞数与点赞关系一起事务更新，重复请求不应重复加减。
- 建议禁止给自己的共享配置点赞。
- 未验证邮箱账号与其他已登录账号行为一致。

### 分享码、查询与排序

- 分享码采用大写形式，例如 `ABC-1234`，数字允许前导零；查询可兼容小写输入。
- 数据库唯一约束保证分享码唯一；随机碰撞时有限重试，不能只在插入前检查是否存在。
- 分享码是查找入口，访问仍需要登录。
- 建议提供分享码精确查询及可复制的站内链接。
- 建议默认按最新发布排序，另提供“最多人使用”“最多点赞”；同分时使用明确的次级排序。
- 列表分页，列表查询不读取五份大文本正文；详情与复制按需读取。
- 职业保存发布时快照，避免作者转职后既有条目突然改变分类。
- 职业仅用于查找，允许跨职业复制。大厅筛选项按二阶职业系组织，查询时匹配整条职业链上的具体 `job_id`，包括共同前置职业、初心者、一转、进阶初心者、进阶一转、二阶、三转、四转，以及适用的宝宝和骑乘形态；异常缺失不拦截分享或复制。

### 发布信息与展示内容

- 共享标题使用原配置名称，说明选填；另展示职业、作者站内昵称、发布时间、更新时间、分享码、使用人数与点赞数。
- 简短说明应帮助新人了解练级地点、装备或技能前提，先不加入复杂标签系统。
- 共享开关按用户要求默认勾选；在开关附近明确列出共享范围，让用户理解保存时会发布或更新五份文件。
- 不公开作者邮箱、游戏账号标识、内部鉴权信息；作者昵称、标题、说明、配置正文均作为纯文本展示。
- 界面沿用现有站点风格；分享入口应醒目，但具体页面布局留到后续设计确认。

## 候选数据划分

以下仅用于讨论边界，字段、约束、索引、接口路径和错误码在最终设计中确定：

- `ke_shared_profiles`：作者、原配置关联、标题/说明、职业快照、分享码、五份配置文本、发布状态、时间和统计缓存。
- `ke_shared_profile_likes`：共享配置与点赞账号的唯一关系。
- `ke_shared_profile_uses`：共享配置与成功复制账号的唯一关系，支持独立人数统计。
- 复制请求的幂等记录：存储方式和保留时长由实施设计确定，不以浏览器禁用按钮代替服务端保证。

沿用现有账号会话、写请求来源校验/CSRF 方案和限流机制。新增接口必须验证拥有者权限、目标角色归属、输入长度和排序参数；共享状态变化与复制之间的并发行为也需要在设计中明确。
