# KE 配置大厅设计

日期：2026-10-23

开发分支：`codex/ke-profile-hall`

状态：完整设计待确认；尚未进入产品实现。

需求来源：[需求确认记录](requirements.md)。

## 1. 目标与约束

让熟悉 KE 配置的玩家发布方案，让其他玩家登录后通过职业、热度或分享码找到方案，并复制为自己的独立配置。

继续使用现有 Cloudflare Worker + Hono、Vite + TypeScript、MySQL 8，不引入新框架、存储服务或依赖。新增数据库迁移，不修改旧迁移，不自动公开既有个人配置。

浏览、详情、分享码查询、发布、更新、撤回、恢复、点赞与复制全部要求有效网页会话。允许 `PENDING_EMAIL` 和 `ACTIVE`，不检查 permission level、邮箱验证或 KE 运行权益；禁用账号、过期及已撤销会话继续拒绝。

第一版不做评论、收藏、装备评分、职业兼容性判定、历史版本浏览、订阅更新或新的管理后台。不增加共享条目总量/每日数量等产品配额；现有个人配置每角色 20 套的规则保持。

## 2. 发布与更新

| 当前状态 | checkbox 文案 | 每次打开编辑器时 | 勾选保存 |
| --- | --- | --- | --- |
| 从未分享 | 同时将此配置共享给他人 | 默认勾选 | 保存个人配置并首次发布 |
| 已发布 | 同时更新共享的配置 | 默认勾选 | 保存个人配置并更新共享快照 |
| 已撤回、原配置仍在 | 同时将此配置共享给他人 | 默认勾选 | 保存个人配置并恢复发布 |

前两行由用户明确指定；第三行为开发方补齐。已撤回时补充“已撤回，勾选保存后重新发布，沿用原分享码”。

- checkbox 显著展示在保存区域附近，整行可点击，支持键盘和可见焦点。
- 勾选时展开“配置说明”多行输入；说明选填，不新增标题输入。
- 标题取本次保存的个人配置 `name`。取消勾选后保存，原共享标题、说明、职业和文件均不改变。
- 编辑已发布/已撤回配置时，说明预填其共享说明；未修改时保留，显式清空后勾选保存则存空字符串。
- 取消勾选只对本次保存生效，不撤回分享，不持久化为下次默认偏好。
- 单纯改动表单不发布；保存才执行。共享快照与此次个人保存必须同事务成功或失败。
- 五份文件按保存的原文镜像，不额外解析或重写。编辑器已有校验和序列化保留。
- 更新保留共享 id、分享码、首次发布时间、点赞和使用人数，更新 `updated_at`。
- 旧配置不会批量发布；只有用户在新界面勾选并保存才发布。

## 3. 生命周期：开发方补齐的默认行为

- 同一原配置最多一个共享条目，由数据库 `source_profile_id` 唯一约束保证。
- 作者可以在自己的配置列表或共享详情撤回分享；撤回是单独操作。
- 撤回后大厅和公开详情不可读、不可点赞或复制；作者通过个人配置接口仍可查看共享状态和说明。
- 再次勾选分享保存时恢复原条目，沿用原分享码、首次发布时间和统计。
- 删除原配置时，在同一事务撤回共享，再删除个人配置。共享快照保留为撤回记录，原配置关联置 NULL，分享码不分配给其他条目。
- 原配置删除后不能从编辑器恢复该共享；以后新建同名个人配置视为新的来源。
- 已被复制的个人配置不因作者更新、撤回或删除而改变或删除。
- 复制来的配置可以再编辑和分享，届时生成属于复制者的新共享条目。第一版不增加转载关系或更新订阅。

## 4. 大厅与复制

### 4.1 查询与展示

新增 `/ke/hall`，在现有导航与 `/ke` 配置页提供“配置大厅”入口。复用站点登录入口；匿名页面仅显示登录提示，不泄露大厅数据。登录后可继续打开原分享地址。

- 分享码精确查询支持 `ABC-1234`、`abc-1234` 和省略连字符的输入；服务端归一化为大写标准格式。
- 职业使用现有本地化字典，按具体 `job_id` 过滤，不推断职业系或技能兼容性。
- 职业由服务端读取源角色记录，发布/更新时保存快照；异常缺失存 NULL，显示“未知职业”，在“全部职业”中可见，不阻止任何分享或复制。
- 默认 `newest`，另支持 `uses`、`likes`；均降序，并以 `created_at DESC, id DESC` 稳定打破平分。
- 每页 20 条，页码分页；改变排序/过滤回第一页。热度变化可导致跨页位置变化，不承诺跨页冻结快照。
- 展示标题、选填说明、职业、作者站内昵称、分享码、点赞数、使用人数和更新时间；作者自己的条目显示管理入口。
- 详情展示完整说明与五份只读文件，提供复制配置、分享码和链接。链接为 `/ke/hall?code=ABC-1234`。
- 列表仅取摘要，不返回五份正文；详情与复制按需读取。API 不公开源角色 aid/cid/nid、作者邮箱、会话或 KE 授权信息。
- 作者使用当前站内昵称；所有用户内容通过纯文本 DOM 写入，不当作 HTML/Markdown 渲染。
- 支持加载、空结果、错误、登录失效；手机和键盘都可完成筛选、点赞和复制。

界面沿用现有站点字体、色彩与导航。具体排布由实现阶段按 `design-taste-frontend` 的 app-screen 流程完成并检查，不重设计全站。

### 4.2 复制与个人配置

“一键复制”指整套五文件复用，无需逐项配置；多个角色时先选目标角色，只有一个时预选，确认后保存。

1. 服务端验证会话、请求来源、目标角色归属；职业不参与权限判断。
2. 锁定仍在发布中的共享条目，从同一事务读取同一版本的五份内容。
3. 用复制者的账号与目标角色 aid/cid/nid 新建个人配置，`is_active = 0`，不覆盖既有配置。
4. 默认名称为共享标题；重名则附加 ` (2)`、` (3)`，为后缀预留现有 64 字符长度。名称比较遵循数据库现有排序规则。
5. 已有 20 套则拒绝，不插入、不计数。没有自己的绑定角色时提示先在 KE 登录角色，不增加邮箱/职业门槛，不创建无角色配置。
6. 返回新配置 id、实际名称和人数；提供前往 `/ke` 编辑的入口，通过查询参数定位目标角色与配置。

复制本身不再次发布。进入编辑器后的默认分享开关规则仍然适用。以上角色选择、重名处理与默认未激活为开发方沿用现有系统补齐。

### 4.3 按账号计数

- 使用人数统计成功复制过该条目的独立账号。同账号多次复制、复制到多个角色、删后重复制都只计一次。
- 作者可复制自己的共享，但不计使用人数；开发方采用此前建议的规则。
- 首次使用关系、个人配置、人数增量与复制回执在同一事务提交，失败均不计数。
- 点赞按 `(shared_profile_id, user_id)` 唯一记录，每人最多一个，可取消，重复请求幂等。
- 作者不能自赞；开发方采用此前建议的规则。
- 点赞数等于有效点赞关系数；使用人数等于唯一使用关系数。更新/撤回/恢复不清零，删除个人副本不减少人数。

## 5. 数据模型

新增一个 MySQL migration，预计 `019_ke_shared_profiles.sql`，实施前重新确认编号。新增四张 InnoDB 表，id 和毫秒时间戳匹配现有 schema。无既有数据回填，不公开个人内容。

| 表 | 字段与关键约束 |
| --- | --- |
| `ke_shared_profiles` | `id`；`author_user_id` 外键；可空且唯一的 `source_profile_id`，引用个人配置、ON DELETE SET NULL；唯一 `share_code CHAR(8)`，ascii_bin；`title VARCHAR(64)`；`description TEXT NOT NULL`；`job_id INT UNSIGNED NULL`；五份 MEDIUMTEXT，NULL 约束与个人配置一致；`status` 为 PUBLISHED/WITHDRAWN；非负 `like_count`/`use_count`；`created_at`/`updated_at` |
| `ke_shared_profile_likes` | `shared_profile_id`、`user_id`、`created_at`；复合主键 `(shared_profile_id, user_id)`；共享和账号外键 |
| `ke_shared_profile_uses` | `shared_profile_id`、`user_id`、`created_at`；复合主键 `(shared_profile_id, user_id)`；仅首次成功复制，作者不写入；共享和账号外键 |
| `ke_shared_profile_copies` | `id`、`user_id`、`request_id`（UUID，ascii_bin）、`shared_profile_id`、`request_hash BINARY(32)`、`result_profile_id`、`result_name`、`created_at`；唯一 `(user_id, request_id)`；保存复制回执，不重复存正文 |

共享无物理删除接口；关系和回执第一版不定时过期。账号外键沿用现有拒绝物理删除约束，不新增注销功能。回执的结果 id 不使用级联删除外键，副本删除后仍可识别旧请求。

索引覆盖作者查找、PUBLISHED + 三种排序（newest/uses/likes），以及带 job_id 的三种排序。正文大列不进入列表 SELECT。具体索引名称由实施者决定，用真实 MySQL 验证查询。

分享码空间为 `26^3 × 10000 = 175,760,000`。用 Web Crypto 均匀生成三个大写字母和四数字，数字保留前导零。唯一约束裁决碰撞，最多重试 8 次；耗尽则整个保存回滚，返回可重试错误。只重试分享码冲突，不掩盖其他唯一键错误。

说明允许空字符串，技术上限 UTF-8 16 KiB，规范换行但不要求非空。标题、五文件及总请求体沿用现有校验和容量限制；不另设共享数量配额。

## 6. API 契约

前缀 `/api/v1/ke`。全部 `Cache-Control: no-store`；错误沿用现有 envelope 与 `KeFailure`/`AuthFailure`。账号 id 沿用现有字符串形式，配置/共享 id 沿用数字形式。

### 6.1 兼容扩展个人配置接口

保持 `POST /profiles` 的 `{ id }` / 201 响应和 `PUT /profiles/:id` 的 204 响应，保留既有字段意义。请求可追加：

```json
{
  "sharing": {
    "enabled": true,
    "description": "可留空的使用说明"
  }
}
```

- 未提供 sharing 或 `enabled: false` 只保存个人配置，旧客户端不会被自动发布。
- `enabled: true` 时，从本次个人保存的内容创建/更新/恢复共享。首次省略 description 用 `''`，更新时省略则保留，显式 `''` 清空；错误类型/长度返回 400。
- `GET /profiles` 摘要和 `GET /profiles/:id` 增加可空 sharing 元数据：`id`、`share_code`、`status`、`updated_at`；详情另带 description。现有字段保留。
- `DELETE /profiles/:id` 保持原响应，其事务内同步撤回关联共享。
- 发布/更新验证源角色仍属当前账号；角色转移时不能取新所有者资料更新旧账号共享。
- 保存成功后重读元数据，显示分享码/共享结果。新建个人配置响应丢失后的同名重试沿用既有冲突行为，不能因重试创建第二条共享。

### 6.2 大厅接口

| 接口 | 请求/响应 |
| --- | --- |
| `GET /shared-profiles` | sort 为 newest/uses/likes，可选 job_id、page；返回 `{ items, page, page_size: 20, total }`，仅发布中 |
| `GET /shared-profiles/code/:code` | 归一化分享码后取详情；撤回/不存在统一 404 |
| `GET /shared-profiles/:id` | 摘要 + 五文件详情；撤回/不存在统一 404 |
| `PUT /shared-profiles/:id/like` | 无业务 body；幂等点赞；返回 `{ liked: true, like_count }` |
| `DELETE /shared-profiles/:id/like` | 幂等取消；返回 `{ liked: false, like_count }` |
| `POST /shared-profiles/:id/copy` | JSON `{ aid, cid, nid, request_id }`；新复制 201，重放 200；返回 `{ profile_id, name, use_count, duplicate }` |
| `DELETE /profiles/:id/sharing` | 仅作者；幂等撤回，204；恢复通过编辑器勾选保存 |

摘要含 `id`、title、description、job_id、`author: { id, display_name }`、share_code、like_count、use_count、liked_by_me、used_by_me、is_mine、created_at、updated_at。列表说明可截短，详情返回完整说明。

page 为正整数、job_id 为非负整数；参数缺省用默认值，未知排序/非法数字返回 400。分享码路径先于 `:id` 注册。SQL 使用参数绑定与固定排序白名单。

状态码：401 未登录；403 非拥有者/自赞；404 目标角色或配置或公开共享不存在；409 个人配置满额/复制回执冲突；400 输入无效；413 请求过大；415 非 JSON；429 请求频率保护；503 账号/数据库不可用或分享码生成重试耗尽。具体错误枚举由实施者统一命名并写入 API 文档，不借用含义不符的错误。

## 7. 事务与重复提交

### 7.1 保存、共享和撤回

沿用个人配置按账号锁定的方式，在同一连接/事务组织个人与共享 repository 操作。不得嵌套当前 `MysqlDatabase.transaction()`，其实现会另取连接。

先锁账号，再读取/锁个人配置和角色并校验归属，最后锁共享条目。保存正文、关联、标题/说明/职业与共享状态一起提交。撤回/删除顺序相同；删除前先置 WITHDRAWN。

source_profile_id 唯一保证单个来源只有一条共享。对既有共享重复更新不生成新码或重置计数。失败时个人保存也回滚，页面保留表单并显示失败。

### 7.2 复制幂等与竞态

- 浏览器为一次确认复制生成 UUID，网络失败重试沿用，明确再次复制才换新 UUID。
- 事务先锁复制者账号，再检查 `(user_id, request_id)` 回执。request_hash 是规范化共享 id + aid/cid/nid 的指纹，不含可变正文。
- 同键不同指纹 409。相同请求且副本仍属于当前账号时返回原 id/name、duplicate=true，不新建/计数；副本已删除则 409，必须主动新发起复制。
- 未命中时锁目标角色并验证归属和上限，再锁共享条目并确认 PUBLISHED。只复制锁后读出的同一版本，不接受前端提交正文。
- 新个人配置、首次使用关系、必要的人数增量和回执一起提交。仅首次使用关系插入成功时增加人数，作者不写该关系。
- 撤回/更新/复制由共享行锁排序：撤回先提交则复制拒绝；复制先完成则副本保留。五文件必须完整来自旧或新版本，不能混合。
- 点赞/取消锁共享条目，只有唯一点赞关系实际变化才原子加减计数，不做内存读取后覆盖计数。
- 所有同账号写先锁账号，再角色/个人配置，最后共享条目，一次操作不锁第二个账号。死锁或超时作为可重试失败处理，回滚不得残留副本/关系/计数。

## 8. 鉴权与容量边界

- 所有接口先校验网页会话，不以 KE 设备 Bearer 替代；不依赖 license 私钥或运行权益。
- 所有写请求校验可信 Origin；有 JSON body 的继续使用现有受限 reader。个人保存新增 sharing 的写路径也补齐来源校验。
- 作者与职业从数据库取得；复制账号从会话取得，目标角色归属从数据库验证。
- checkbox 附近说明其他已登录用户可读取五文件，让默认勾选的共享范围清晰可见。不展示邮箱、内部角色标识、会话与 KE 密钥字段；作者自行写入文件的内容仍按原文共享。
- 复用现有 auth rate-limit 对复制、发布/更新和点赞写入按账号保护；初始频率值由实施者按现有约定决定并记录。频率保护不作为共享条目数量限制。
- 日志不记录五文件、完整说明、cookie 或 token。不改 KE bind/start/heartbeat/stop 的授权逻辑。

## 9. 验收与实施边界

| 范围 | 必须验证 |
| --- | --- |
