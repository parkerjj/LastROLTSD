# Deployment

Run `pnpm install`, `pnpm --filter web build`, and `pnpm wrangler d1 migrations apply lastroweb-local --local` for local validation. Staging and production bindings in `wrangler.toml` intentionally use placeholder database IDs; set real IDs with Wrangler configuration before deployment and store upload/admin keys as Worker secrets.

For staging, create a D1 database, replace the staging placeholder ID, apply migrations, seed `market_sources.api_key_hash` with the lowercase hexadecimal SHA-256 hash of a newly generated source key, set a random `CURSOR_SECRET` of at least 16 characters and the optional `ADMIN_SECRET` with `wrangler secret put`, build the web assets, deploy with `wrangler deploy --env staging`, and verify `/api/health`, a redacted smoke upload, and a search request. Production follows the same sequence with `--env production`. Roll back by deploying a previously recorded Worker version; do not roll back migrations that have already changed persisted data without a reviewed forward migration. Verify a D1 export/backup before enabling long retention.
